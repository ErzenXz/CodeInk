# Security policy

## Supported versions

Security fixes are made on the current Production release from `main`. The current Early Access release from `development` may also receive a fix or be replaced by a newer prerelease. Older releases are not maintained individually; users should update to the latest build for their channel.

## Report a vulnerability

Use [GitHub's private vulnerability report form](https://github.com/ErzenXz/CodeInk/security/advisories/new). Include the affected CodeInk version and channel, operating system, steps to reproduce, the impact, and a minimal proof of concept if one is needed. Keep credentials and unrelated private source code out of the report.

Please do not open a public issue or pull request containing exploit details. The maintainer will review the private report, work with you to understand it, and coordinate a fix and disclosure. Response and release timing depend on the issue; no fixed service-level commitment is promised.

For non-security bugs, use the [bug report template](.github/ISSUE_TEMPLATE/bug_report.md). For issues in an independently installed agent or its provider service, contact that agent's maintainers as well.
