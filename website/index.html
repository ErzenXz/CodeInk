How it connects

Your agent does the work. CodeInk gives it a desk.

  1. Install an agent

    Use the agent’s own installer. CodeInk never ships or fetches an agent CLI for you.

  2. Sign in with its CLI

    Your existing account and plan stay with the agent. There’s no CodeInk account to create.

  3. Open a project in CodeInk

    Pick the agent, choose a model from its catalog, and start a session. Follow replies, commands, file reads, and approvals next to your files, Git changes, and a terminal.

  • Accounts Each agent keeps its own sign-in and controls its own connection to model providers.
  • Credentials CodeInk doesn’t collect your CLI credentials.
  • Sessions CodeInk keeps its session data on your computer.

Before you install

The first builds may be unsigned

macOS may block the app on first open. After checking where it came from, open System Settings, then Privacy & Security, and choose Open Anyway. Windows may show a SmartScreen notice. On Linux, make the AppImage executable with chmod +x.

Verify your download

Every release includes SHA256SUMS.txt. Compare it with shasum -a 256 <file> on macOS or Linux, or Get-FileHash <file> in PowerShell. Only download from ErzenXz/CodeInk releases, or build from source.

Early Access is a separate app

Early Access contains the newest changes from development. It installs as CodeInk Early Access, next to the production app, and keeps its own session data. Sessions don’t move between the two.

Set up an agent first

Install at least one agent with its own instructions and sign in using its CLI. CodeInk finds the command on your PATH and uses the account you already have.

Some features don’t work with every agent yet

CodeInk is a fork of OpenCode. Some upstream features, including cloud sharing and session forking, aren’t available across all agents yet.
