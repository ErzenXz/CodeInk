# CodeInk coding agent reliability research

This is the initial September 24 research snapshot. For the current implementation, fixes, live probes, and remaining limits, see [the September 27 Pi comparison and agent audit](codeink-pi-audit.md).

Checked 2026-09-24 against first-party documentation and the local CodeInk adapter (`packages/desktop/src/main/adapters/codeink.ts`, AI SDK 7.0.113). This is an implementation guide, not a claim that a free model has passed an end-to-end CodeInk test.

## What the current harness already does

The desktop adapter gives the model one `terminal` tool, runs `streamText` with `stopWhen: stepCountIs(24)`, sets a two-minute model-step timeout, and sends OpenRouter `x-session-id`. The session ID is useful: OpenRouter uses it as a sticky routing key for prompt caching and accepts it in the header. [AI SDK tool loop](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling) · [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching)

## Recommended changes, in order

1. **Gate model selection on actual tool support.** Fetch OpenRouter model metadata and require `supported_parameters` to contain `tools`; check `context_length` and the exact `:free` slug before a coding run. Send `provider.require_parameters: true` when tools are required, so an endpoint cannot silently ignore them. Do not silently switch to a paid or tool-less fallback; a user-selected free model should stay free. Model availability and capabilities change, so refresh rather than hardcode a permanent list. [Models API](https://openrouter.ai/docs/api/api-reference/models/get-models) · [Tool calling](https://openrouter.ai/docs/guides/features/tool-calling) · [Provider routing](https://openrouter.ai/docs/guides/routing/provider-selection)
2. **Retry provider calls only at safe boundaries.** AI SDK `streamText` defaults to `maxRetries: 2` (two retries after the first attempt), supports `abortSignal`, and offers total, step, and stalled-chunk timeouts. Make the chosen retry count explicit and observable, honor cancellation, and avoid stacking another unbounded retry loop around it. Retry transient transport, 429, and server failures with a bounded backoff; surface authentication, payment/quota, invalid model, unsupported tools, and malformed requests as actionable terminal states. A failed stream after output or tool execution should be resumed from reconciled history, never replayed by re-running shell commands. [AI SDK streamText](https://ai-sdk.dev/docs/reference/ai-sdk-core/stream-text) · [OpenRouter error examples](https://openrouter.ai/docs/agent-sdk/call-model/text-generation) · [AWS idempotent retry guidance](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/)
3. **Separate model errors from tool errors.** AI SDK streams provider errors as `error` parts and tool execution errors as `tool-error` parts; schema failures include `NoSuchToolError` and `InvalidToolInputError`. Show the command, exit status, output, duration, and an explicit failure state in the session timeline. A shell command returning exit code 1 is a tool result the model can inspect and repair; a spawn failure, timeout, or invalid tool call needs a distinct visible reason. Use a stable tool-call ID to update one card through pending, running, and finished states. [AI SDK tool error handling](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)
4. **Let the agent recover from a failed check, but never auto-repeat a mutating command.** The terminal tool should return structured `stdout`, `stderr`, `exitCode`, `signal`, `timedOut`, and `truncated` data; the agent can revise its next action after seeing a failed test. Retrying an arbitrary shell command may duplicate file edits or external effects. If automatic command retry is desired, restrict it to an explicit allowlist of idempotent reads and assign each execution an identity. [AWS retry safety](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) · [Anthropic agent design](https://www.anthropic.com/engineering/building-effective-agents)
5. **Keep the prompt and tool schema stable; measure cache savings.** The existing OpenRouter session ID supports sticky routing, but cache benefit still depends on provider/model support and repeated prompt prefixes. Put durable instructions and tool definitions first, changing repository context and tool results later. Expose cache read/write tokens and resolved model/provider in diagnostics. OpenRouter documents provider-specific automatic or explicit `cache_control` rules; add breakpoints only after checking the chosen provider and measuring a real hit. OpenRouter response caching is a different feature: because it can replay tool calls, leave it off for live coding runs. [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching) · [OpenRouter response caching](https://openrouter.ai/docs/guides/features/response-caching)
6. **Manage context by valid transcript boundaries.** AI SDK supports changing messages in `prepareStep` for long runs. Compress older observations while retaining current user intent, relevant repository rules, recent tool calls with their matching results, and a factual summary of verified findings. The adapter currently trims by serialized character count, which is only a rough proxy for model context; use model limits and token usage to trigger compaction before overflow, then verify the next turn continues correctly. [AI SDK `prepareStep`](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling) · [Models API context length](https://openrouter.ai/docs/api/api-reference/models/get-models)
7. **Measure agent quality with executable outcomes.** Build a small local benchmark of representative CodeInk coding tasks: reported UI bug, failing test, multi-file change, unsupported tool model, 429, stalled stream, declined command, cancellation, and interrupted continuation. Save traces of model turns, tool calls/results, errors, usage, model, and cache counters without storing secrets. Grade final filesystem state and relevant tests, plus failure recovery and truthful reporting; repeat runs because one successful trial does not establish reliability. [Anthropic agent evaluation](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) · [OpenAI trace and eval guidance](https://developers.openai.com/api/docs/guides/agent-evals)

## Free-model test protocol

Select a currently listed tool-capable `:free` model, then run one read-only terminal call and one sandboxed edit/test task. Record exact model slug, returned model, tool-call correctness, response and tool errors, total turns, latency, tokens, cache read/write tokens, and final test result. Repeat after a new session and after a failure injection. OpenRouter's free collection changes over time and its free tier has request caps; excessive retries can exhaust the allowance, so keep tests small and bounded. [Free model collection](https://openrouter.ai/collections/free-models/) · [OpenRouter pricing](https://openrouter.ai/pricing) · [Tool calling](https://openrouter.ai/docs/guides/features/tool-calling)

The model is one component of the result. Better instructions help, but reliable execution also needs capability checks, sound tool contracts, controlled retries, state reconciliation, and outcome-based evals. [Anthropic agent design](https://www.anthropic.com/engineering/building-effective-agents)
