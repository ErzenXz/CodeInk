# CodeInk Agent reliability audit against Pi

Checked 2026-09-27. This note compares the local built-in CodeInk adapter with current first-party Pi, AI SDK, and gateway documentation. Pi is a reference for small agent-loop behavior, not a dependency or a feature checklist.

## Reference behavior

| Area | First-party reference | CodeInk state |
| --- | --- | --- |
| Tool surface | Pi defaults to `read`, `bash`, `edit`, and `write`; `grep`, `find`, and `ls` are available but optional. [Pi settings](https://pi.dev/docs/latest/settings) | The model receives one `terminal` tool with a command string; plan mode receives none. Shell commands can read and edit files, but no separate read/edit tool or built-in subagent tool exists. |
| Steering | Pi delivers steering after the current assistant turn and its tool calls; follow-ups enter after pending work ends. [Pi SDK](https://pi.dev/docs/latest/sdk) · [Pi RPC](https://pi.dev/docs/latest/rpc-commands) | CodeInk has `steer`, but this adapter does not expose a distinct follow-up queue. Terminal calls in one model batch now run in order. A steer skips calls that have not started, resolves a pending approval, and enters the next model request after the prior tool results. Promoting a steer resets that instruction's model-step allowance while reply IDs continue increasing. |
| Context | Pi summarizes older context when token usage approaches the model window, reserving response space. It retains the raw session history separately. [Pi compaction](https://pi.dev/docs/latest/compaction) | CodeInk uses a 96 KiB character heuristic. It now prunes older reasoning/tool parts and drops oldest whole user turns in the actual in-flight request. This is not token-aware compaction and is not a strict upper bound: one current user turn, including images and its tool results, is kept intact even if it exceeds the heuristic. It does not synthesize a summary of older verified work. |
| Extensibility | Pi's executable extensions can register tools and commands; subagents are supplied by extensions/packages. [Pi extensions](https://pi.dev/docs/latest/extensions) · [Pi subagent extension](https://pi.dev/packages/pi-subagent-extension) | CodeInk's built-in adapter has no subagent, question, or plan tool. Its plan access mode prompts for a text plan without tools. A UI affordance should not imply a built-in subagent capability. |

## Gateway and loop findings

- OpenRouter says models that support tool calling can be filtered by `supported_parameters=tools`. Advertising only `tool_choice` does not establish tool support. Its `require_parameters` routing option prevents an endpoint from silently dropping required parameters. The discovery predicate was changed to require `tools`, with a fixture that rejects a `tool_choice`-only model. [OpenRouter tool calling](https://openrouter.ai/docs/guides/features/tool-calling) · [OpenRouter provider selection](https://openrouter.ai/docs/guides/routing/provider-selection)
- AI SDK `streamText` supports `stopWhen`, `prepareStep`, explicit `maxRetries`, abort signals, and per-step timeouts. It emits provider failures as `error` stream parts and tool failures as `tool-error` parts. CodeInk uses `stopWhen` to stop after the current tool batch when a steer is pending; the adapter can then append the finished tool messages before the new user message. [AI SDK streamText](https://ai-sdk.dev/docs/reference/ai-sdk-core/stream-text) · [AI SDK tool calling](https://ai-sdk.dev/docs/ai-sdk-core/tools-and-tool-calling)
- OpenRouter uses `x-session-id` as a sticky routing key for prompt cache locality. CodeInk sends one stable session ID and records cache read/write token usage. A stable ID improves routing opportunity but does not prove a cache hit. Provider and model support still determine caching. [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching)
- CodeInk disables AI SDK automatic retries and makes at most three manual retries for transient gateway errors before any text or terminal effect. Authentication, restriction, and unsupported-model errors remain terminal; retrying a partially streamed or tool-executed turn could replay side effects. AI SDK documents its automatic retry default and error handling. [AI SDK streamText](https://ai-sdk.dev/docs/reference/ai-sdk-core/stream-text)

## Regressions and live probe

The focused adapter suite (`bun test src/main/adapters/codeink.test.ts` from `packages/desktop`) has 14 passing tests; `bun typecheck` in that package passes. Two new regressions were red before the fixes: (1) a second tool command executed while the first was still running, despite a steer; (2) a steer left an approval pending and blocked the turn. A follow-up assertion also caught the durable message order error: the steer appeared before the previous tool result. The tests now cover skipped commands, approval resolution, and `tool result → steer → later assistant reply` order on a subsequent prompt. An in-flight context regression shows older whole turns omitted from the second request after a 16 KiB tool result, while the latest instruction and current tool call remain. A two-step boundary regression caught rejection of a pending steer at the limit; it now checks a fresh allowance, unique reply IDs, and rejection of an unsteered turn at its limit. All commands run only in temporary directories.

One live, tool-capable `:free` OpenRouter sandbox probe passed using the already configured key, without printing it: `cohere/north-mini-code:free`, two upstream requests, one approved terminal command, successful file creation and exact-content check, and a final model reply. The probe took about 4.3 seconds and reported 717 input tokens, 445 output tokens, **0 cache-read** and **0 cache-write** tokens. It proves this model worked for this single simple edit/test; it does not prove prompt caching, broader model quality, quota availability later, or multi-step project work. The proxy capped upstream requests at three and did not touch the real project.

A second, less guided coding probe used a temporary Bun project with a failing `formatName` unit test. The task described expected behavior without giving shell commands or a patch. Under a strict five-request cap, the same free model made five HTTP-200 upstream requests and five terminal approval attempts; four commands completed and one was denied by the sandbox command guard. The test still failed afterward (exit 1 before and after), the function did not gain a `.trim()` call, and the model produced no final reply before the local cap returned 403. Usage was 2,783 input and 527 output tokens, again **0 cache-read/write**. **This coding probe is inconclusive:** the guard rejected any command containing `/`, `$`, `~`, `..`, or several blocked command names, so it may have denied a legitimate edit; the ephemeral harness did not retain the exact command text after exit. The five-request cap also ended the run.

The same coding fixture and model were then rerun with each proposed command reviewed individually and an eight-request cap. This run passed: the independent Bun test changed from exit 1 to exit 0. The model inspected the two files, wrote a minimal `formatName` fix using `first.trim()`, `last.trim()`, `filter(Boolean)`, and `join(' ')`, then ran `bun test` and gave a final explanation. Its seven approved terminal calls were `ls -la`, three reads of `format.ts`, one read of `format.test.ts`, one here-document edit of `format.ts`, and `bun test`. No command was denied; all tool calls completed. All eight upstream responses were HTTP 200. Usage was 5,080 input and 887 output tokens, with **0 cache-read/write**. The reported 102-second elapsed time includes manual approval delays and is not a model-latency measure. This is one successful small bug fix, with an eight-request ceiling and no real-project writes. No other model was tried.

## Remaining implementation limits

The adapter still offers only the `terminal` tool; subagents, interactive questions, and a dedicated plan tool require explicit product and protocol work. Non-image attachments currently send only a filename, MIME type, and local path as text; images are sent as file bytes. The context-size heuristic now removes older whole turns from model requests, but it needs a token-aware, transcript-safe summary before it can promise reliable continuation near model limits. The newest user instruction and binary image content are deliberately not silently truncated. OpenRouter free model availability, tool fidelity, and rate limits are external and can change; the transport probe and one corrected bug-fix success do not establish broad coding reliability.
